## 二、更新了新的测评方法

### 2.1 原方法的问题

此前，我的评估流程采用「QA 对问答」形式来验证压缩效果：

1. 基于原始文档生成若干问答对（Q&A）
2. 让模型基于压缩后的文档回答这些问题
3. 用裁判模型对比「参考答案」与「实际回答」的匹配度

但在实际评测中发现这种方法存在明显缺陷：

| 问题类型 | 具体表现 |
|---------|---------|
| 信息碎片化 | QA 对将完整信息拆解为孤立问题，丢失了文档的逻辑连贯性 |
| 任务失真 | 压缩后真正要服务于「写摘要」「提取论点」等下游生成任务，而非回答零散问题 |
| 幻觉难发现 | 模型在回答问题时容易"圆谎"，即使压缩文本有缺陷，也能通过推理编造答案 |

例如，在之前的 anchor_v2 版本评测中，裁判模型发现：模型会将「已完成作品」误判为「未完成」，或者捏造出「北宋延续至今」「灯与丁谐音」等原文中不存在的信息。

---

### 2.2 新方法的思路

我决定转向双轨生成 + 标杆对比的 Task-Oriented Eval：

1. **基准任务生成**：用高性能模型（ali-kimi-k2.5）基于未压缩的原始文档，执行一个真实的下游任务，如"写 500 字执行摘要"
2. **测试任务生成**：基于压缩后的文档，执行完全相同的任务
3. **LLM-as-a-Judge 对比**：让裁判模型评估「测试输出」相对于「基准输出」在三个维度的表现

```python
def _build_task_prompt(self, task_instruction, content):
    return f"""# Role

# Task
请基于提供的【参考文本】，完成以下生成任务：
【{task_instruction}】
# Rules
1. 绝对忠于参考文本，严禁引入外部知识或脑补细节。
2. 保持逻辑严密，结构清晰。如果参考文本中缺乏某些信息，请在生成时自然略过，不要自行虚构。
```

基于 4_judge_scores 目录下 anchor_v2 的失败案例分析，我发现它存在以下问题：

| 问题 | 根因 |
|------|------|
| 过度压缩导致信息截断 | 过度追求极限压缩，忽视保真度 |
| 幻觉与错误重构 | 「反思维链」约束过强，模型靠「凭印象填补」 |
| 结构误判 | 缺乏对「保真底线」的约束 |

因此，我设计了 **Anchor_V3**（核心改进如下）：

```python
if prompt_version == "anchor_v3":
    return f"""# Role
你是一个极高素养的文档压缩专家。你的任务是在**保证事实完整性**的前提下，对文档进行精简。

1. **保真优先**：压缩是对信息的提炼，不是重构。严禁在输出中引入原文未提及的事实、数据、概念。
2. **推理但不臆造**：允许基于原文信息进行合理推断，但禁止捏造具体数据或细节。
```
